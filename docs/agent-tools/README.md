# Agent tool reference

What each app's AI agent can call, generated from the definitions themselves — not
written by hand, and regenerated by `npm run agent-docs`.

| file                                         | surface                                   | generated from                          |
| -------------------------------------------- | ----------------------------------------- | --------------------------------------- |
| [slides.md](slides.md)                       | the slides agent's tools                  | `TOOLS` in `slides-skill.ts`            |
| [docs.md](docs.md)                           | the docs agent's tools                    | `AGENT_TOOLS` in `docs/…/tools.ts`      |
| [docs-commands.md](docs-commands.md)         | the commands `apply_commands` takes       | the `Command` type in `commands.ts`     |
| [sheets.md](sheets.md)                       | the sheets agent's tools                  | `WORKBOOK_TOOLS` in `sheets/…/tools.ts` |
| [sheets-operations.md](sheets-operations.md) | the operations `propose_operations` takes | `workbookOperationSchema`               |
| [pdf.md](pdf.md)                             | the pdf agent's tools                     | `AGENT_TOOLS` in `pdf/…/tools.ts`       |

Docs and sheets each expose most of their capability through a single tool that
takes a list of operations, so their real surface is the second file, not the
first: 10 commands and 52 operations against 15 and 9 tools.

## Why these are generated

A tool's shape is declared once, in a schema. What the model is _told_ about that
shape is prose in a system prompt, written separately and never re-checked. When
the two disagree nothing fails — the model just gets bad instructions, and the
symptom is output that looks like the model being stupid.

So `npm run agent-check` (which CI runs) enforces both directions:

- these files match the definitions, and
- no prompt names something tool-shaped that no tool provides, which is what
  catches a rename that left the prose behind.

It runs alongside `tools/agent-reachability.mjs`, which asks the neighbouring
question: which app capabilities the agent has no tool for at all.

Argument names and enum values are read out of the schemas, so a word only needs
listing in the generator's `NOT_TOOLS` allowlist if it is genuinely neither — a
protocol tag, an endpoint name, or vocabulary a prompt invented for an example.
